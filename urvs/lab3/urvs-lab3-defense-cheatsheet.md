# ЛР3 За 1 Страницу

## 1. Что делает программа

```text
P0 создаёт канал K1
P0 порождает P1 и P2
P1 и P2 по очереди пишут данные в K1
P0 читает из K1 и выводит результат
```

## 2. Главная схема

```text
                 pipe(K1)
        +-------------------------+
        | K1[0] -> read end       |
        | K1[1] -> write end      |
        +-------------------------+

P1 --------------------\
                        \
                         >==== K1 ====> P0
                        /
P2 --------------------/
```

## 3. Кто какие концы канала держит

```text
P0:
  читает
  K1[0] открыт
  K1[1] закрыт

P1:
  пишет
  K1[1] открыт
  K1[0] закрыт

P2:
  пишет
  K1[1] открыт
  K1[0] закрыт
```

## 4. Что обычно спрашивают

1. Почему канал создают до `fork()`?  
   Потому что после `fork()` дескрипторы наследуются дочерними процессами.

2. Почему надо закрывать лишние концы?  
   Иначе возможны зависания, и `read()` не увидит конец данных.

3. Что такое `K1[0]` и `K1[1]`?  
   `K1[0]` это чтение, `K1[1]` это запись.

4. Почему `P2` не должен писать раньше `P1`?  
   По условию нужен определённый порядок. Значит, нужна синхронизация.

5. Как завершается родитель?  
   `P0` читает данные, затем ждёт дочерние процессы через `wait` или `waitpid`.

## 5. Что выучить из лекций

```text
st4:
  fork
  pipe
  read/write
  wait/waitpid
  наследование дескрипторов

st5:
  signal
  kill
  синхронизация процессов
```

## 6. Короткий ответ на защиту

```text
Неименованный канал создаётся в P0 до fork().
После fork() P1 и P2 наследуют дескрипторы.
Писатели закрывают конец чтения, родитель закрывает конец записи.
P0 читает из K1, а P1 и P2 последовательно записывают данные.
Для правильного порядка используется синхронизация.
```
