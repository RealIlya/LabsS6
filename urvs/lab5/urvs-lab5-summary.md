# ЛР5 — Summary

## Вариант 2

Два дочерних процесса после завершения очередного цикла работ передают через **один и тот же сегмент разделяемой памяти** очередные четыре строки стихотворения.  
`P1` передает нечетные четверостишия, `P2` — четные.  
По условию рассматривается сценарий, в котором процессы работают **с разной скоростью**.  
Родительский процесс собирает полное стихотворение и выводит его после завершения работы обоих процессов.  
Решение должно использовать **аппарат семафоров**.

## Что реализовано

- один сегмент shared memory: `shmget()`, `shmat()`, `shmdt()`, `shmctl()`
- один набор семафоров: `semget()`, `semctl()`, `semop()`
- два дочерних процесса: `P1`, `P2`
- `P1` отправляет 1, 3, 5, 7-е четверостишия
- `P2` отправляет 2, 4, 6, 8-е четверостишия
- `P0` принимает фрагменты, раскладывает их по позициям и печатает готовое стихотворение

## Схема синхронизации

```text
SEM_EMPTY = память свободна
SEM_FULL  = в памяти есть новые данные
SEM_MUTEX = критическая секция
```

```text
P1/P2:
  wait(SEM_EMPTY)
  wait(SEM_MUTEX)
  write shared memory
  post(SEM_MUTEX)
  post(SEM_FULL)

P0:
  wait(SEM_FULL)
  wait(SEM_MUTEX)
  read shared memory
  post(SEM_MUTEX)
  post(SEM_EMPTY)
```

## Что важно сказать на защите

1. Используется **один общий сегмент памяти**, а не отдельные сегменты на каждого потомка.
2. Семафоры нужны, чтобы не было одновременной записи и чтения одного и того же буфера.
3. Родитель не печатает стихотворение сразу по строкам, а сначала **компонует** его в результирующий массив.
4. После завершения работы IPC-ресурсы нужно удалить: `shmdt()`, `shmctl(..., IPC_RMID, ...)`, `semctl(..., IPC_RMID, ...)`.

## Как показывать на защите

Для демонстрации удобно использовать запуск с разными задержками:

```bash
./c/lab5.out 80 220
```

Либо можно использовать значения по умолчанию, где задержки тоже различаются.

Это свойство демонстрационного сценария, а не отдельное ограничение пользовательского ввода.
