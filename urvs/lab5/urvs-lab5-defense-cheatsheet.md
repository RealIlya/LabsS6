# ЛР2 -> ЛР3 -> ЛР5

Эволюция межпроцессного взаимодействия.

## 1. ЛР2: обмен через файл

```text
P0 ----запись----> FILE ----чтение----> P1
```

Что здесь есть:

- `fork()`
- файловый ввод-вывод
- простая координация через задержки или маркер конца

Особенность:

- данные лежат во внешнем объекте: в файле;
- обмен медленный и грубый;
- это скорее модель «процессы работают с одним файлом».

## 2. ЛР3: обмен через программный канал

```text
          signal
P2 -------------> P1
 \               /
  \             /
   \--write--> K1 --read--> P0
```

Что нового:

- `pipe()`
- `read()`, `write()`
- `sigaction()`, `kill()`, `sigsuspend()`
- синхронизация через сигнал

Особенность:

- данные идут напрямую между процессами;
- файла уже нет;
- появляется настоящий IPC на уровне UNIX;
- появляется явное управление порядком работы процессов.

## 3. ЛР5: shared memory + semaphores

```text
                 +------------------+
P1 --write-----> | shared memory    | <----read-- P0
                 +------------------+
                        ^
                        |
P2 --write--------------+

Семафоры управляют доступом к памяти
```

Логика семафоров:

```text
SEM_EMPTY  -> память свободна
SEM_FULL   -> в памяти есть данные
SEM_MUTEX  -> критическая секция
```

Типовой цикл:

```text
P1/P2: wait(empty) -> wait(mutex) -> write -> post(mutex) -> post(full)
P0:    wait(full)  -> wait(mutex) -> read  -> post(mutex) -> post(empty)
```

Что нового:

- `shmget()`, `shmat()`, `shmdt()`, `shmctl()`
- `semget()`, `semctl()`, `semop()`
- критическая секция
- взаимное исключение
- ручное управление IPC-ресурсами ядра

## 4. Смысл эволюции

```text
ЛР2: "обмен через файл"
ЛР3: "обмен через pipe + сигнал"
ЛР5: "совместная память + семафорная синхронизация"
```

Или совсем коротко:

```text
Файл  ->  Канал  ->  Общая память
Маркер -> Сигнал -> Семафоры
```
