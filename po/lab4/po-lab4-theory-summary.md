# Краткое саммари по теории к лабораторной работе №4

## 1. Общая цель работы

Лабораторная работа посвящена построению приложения «Универсальный калькулятор». По методичке калькулятор должен вычислять выражения в трёх режимах: для `p`-ичных чисел, простых дробей и комплексных чисел. Дополнительно требуется работа с памятью, буфером обмена, системой справки и графическим интерфейсом в стиле Windows.

Главная идея работы состоит в том, чтобы собрать одно приложение из нескольких связанных подсистем:

1. иерархия классов чисел;
2. иерархия редакторов;
3. память;
4. процессор;
5. управление калькулятором;
6. интерфейс пользователя.

## 2. Иерархия классов `TANumber`

Базой числовой модели выступает абстрактный класс `TANumber`. Он задаёт общий интерфейс для всех поддерживаемых числовых типов. От него наследуются:

1. `TPNumber` — `p`-ичные числа с основанием `2..16`;
2. `TFrac` — простые дроби;
3. `TComp` — комплексные числа.

В `TANumber` сосредоточены операции, которые должны поддерживать все числа:

1. проверка на ноль;
2. копирование значения;
3. сложение, вычитание, умножение, деление;
4. сравнение;
5. вычисление квадрата;
6. вычисление обратного значения;
7. получение строкового представления числа.

Такой подход даёт полиморфизм: память, процессор и управление калькулятором работают через общий тип `TANumber`, а конкретная реализация операции определяется в наследнике.

## 3. Иерархия редакторов

Для ввода значений используется абстрактный редактор `AEditor`. Он отвечает за строковое представление редактируемого числа и за базовые операции редактирования:

1. добавление цифры;
2. добавление нуля;
3. добавление разделителя;
4. удаление последнего символа;
5. очистка;
6. смена знака.

От `AEditor` наследуются специализированные редакторы:

1. редактор `p`-ичных чисел;
2. редактор простых дробей;
3. редактор комплексных чисел.

Смысл такого разделения в том, что правила ввода зависят от типа числа. Для `TPNumber` важны основание системы счисления и десятичная точка, для `TFrac` — символ `/`, для `TComp` — разделитель действительной и мнимой частей.

## 4. Память `TMemory`

`TMemory` хранит одно число типа `TANumber` и состояние памяти. По методичке память может находиться в двух состояниях:

1. `On` — память включена;
2. `Off` — память выключена.

Основные операции памяти:

1. `Store` — записать число;
2. `Read` — получить копию числа;
3. `Add` — прибавить к числу в памяти новое значение;
4. `Clear` — очистить память и перевести её в нулевое состояние.

Память работает не с конкретным числом, а с абстрактным `TANumber`. Это позволяет использовать одну и ту же реализацию для всех режимов калькулятора.

## 5. Процессор `TProc`

Процессор выполняет вычисления над числами. Его основные данные:

1. левый операнд и результат;
2. правый операнд;
3. текущая бинарная операция;
4. поле ошибки.

Процессор поддерживает:

1. бинарные операции: `Add`, `Sub`, `Mul`, `Dvd`;
2. унарные функции: `Rev`, `Sqr`;
3. установку левого и правого операндов;
4. установку и сброс операции;
5. полный сброс в начальное состояние.

Логически процессор не отвечает за ввод и интерфейс. Его задача — хранить операнды и выполнять вычисление по уже выбранной операции или функции.

## 6. Управление калькулятором `TCtrl`

`TCtrl` связывает редактор, процессор, память и буфер обмена. Это центральный координатор приложения. Он:

1. принимает команду пользователя;
2. определяет, к какой подсистеме относится команда;
3. вызывает нужный метод редактора, памяти или процессора;
4. возвращает строку результата и актуальное состояние.

В методичке для `TCtrl` выделены состояния `TCtrlState`:

1. `cStart` — начальное состояние;
2. `cEditing` — ввод и редактирование;
3. `FunDone` — выполнена функция;
4. `cValDone` — значение введено;
5. `cExpDone` — выражение вычислено;
6. `cOpChange` — операция изменена или выбрана;
7. `cError` — возникла ошибка.

Наличие явных состояний позволяет описывать поведение калькулятора таблицей переходов и диаграммой состояний.

## 7. Интерфейс `TClcPnl`

Интерфейс должен обеспечивать:

1. ввод команд кнопками и с клавиатуры;
2. отображение текущего значения;
3. отображение состояния памяти;
4. доступ к буферу обмена;
5. переключение режима работы;
6. вызов справки.

По методичке в форме присутствуют:

1. обработчик нажатия кнопки `ButtonClick`;
2. обработчик клавиатуры `FormKeyPress`;
3. команды меню;
4. отображение строки числа и состояния памяти.

Интерфейс не должен выполнять вычисления сам. Его задача — преобразовать действия пользователя в команду и передать её в `TCtrl`.

## 8. UML-отношения, которые используются в работе

Для понимания архитектуры важны базовые отношения UML:

1. обобщение — отношение наследования между базовым и производным классом;
2. ассоциация — устойчивая связь между объектами;
3. зависимость — временное использование одного класса другим;
4. агрегация — связь «целое-часть» без жёсткой зависимости по времени жизни;
5. композиция — сильная форма владения, при которой часть живёт вместе с целым.

В данной лабораторной:

1. обобщение используется в иерархиях `TANumber` и `AEditor`;
2. ассоциация и композиция возникают между `TCtrl`, `TProc`, `TMemory`, редактором и интерфейсом;
3. зависимость проявляется там, где класс временно использует другой класс через параметры, возвращаемые значения или вызовы методов.

## 9. Диаграммы состояний

Диаграмма состояний нужна для описания поведения объекта во времени. Для калькулятора она особенно полезна, потому что реакция на одну и ту же команду зависит от текущего состояния: вводится ли число, выбрана ли операция, вычислено ли выражение, возникла ли ошибка.

Основные элементы диаграммы состояний:

1. начальное состояние;
2. конечное состояние;
3. обычные состояния;
4. переходы между состояниями;
5. события, вызывающие переход;
6. действия, выполняемые при переходе или в состоянии.

## 10. Итог

Теоретическая основа лабораторной работы №4 — это объединение нескольких ранее реализованных компонентов в одно универсальное приложение на базе общих абстракций. Ключевая идея состоит не в добавлении отдельных калькуляторов в одну форму, а в построении общей объектной модели, где разные типы чисел, редакторы и вычислительные механизмы согласованы через абстрактные интерфейсы и отношения UML.
