# Ответы на контрольные вопросы к лабораторной работе №1

Источник формулировок вопросов: `lab1/_extracted_lab1/document.md`.

## 1. Конвертор из 10-й системы в p-ичную (`Conver_10_P`)

1. Инкапсуляция - это объединение данных и операций над ними в одном типе с контролем доступа к внутреннему состоянию.
2. Поле в классе задаётся объявлением внутри класса: `[модификатор] [тип] [имя];`, например `private int value;`.
3. Метод задаётся сигнатурой и телом: `[модификатор] [тип_возврата] Имя(параметры) { ... }`.
4. Простое свойство задаётся как `public int X { get; set; }` либо с явными аксессорами.
5. Особенности методов класса: имеют модификаторы доступа, сигнатуру, могут быть `static`/экземплярными, могут возвращать значение или `void`, могут быть перегружены.
6. Видимость идентификаторов определяется модификаторами доступа: `private`, `protected`, `internal`, `public` и их комбинациями.
7. Статические методы принадлежат типу, а не объекту; вызываются без создания экземпляра и не имеют доступа к нестатическим членам без ссылки на объект.
8. Статический класс нельзя инстанцировать; он может содержать только статические члены и используется как контейнер утилитарной логики.

## 2. Конвертор из p-ичной системы в 10-ю (`Conver_P_10`)

1. Инкапсуляция - механизм сокрытия внутренней реализации и предоставления контролируемого интерфейса.
2. Поле описывается как `[модификатор] [тип] [имя];`.
3. Метод описывается как `[модификатор] [тип_возврата] Имя(параметры) { ... }`.
4. Простое свойство: `public double Value { get; set; }`.
5. Методы класса описывают поведение типа, могут быть параметризованы, перегружены и иметь разные уровни доступа.
6. Видимость членов задаётся модификаторами доступа; по умолчанию члены класса `private`.
7. Статические методы работают без состояния конкретного объекта и обычно применяются для чистых вычислений.
8. Статические классы применяются, когда логика не требует экземпляров и хранится на уровне типа.
9. Вызов статического метода выполняется через имя класса: `Conver_P_10.dval("A5.E", 16)`.

## 3. Редактор чисел (`Editor`)

1. `protected` - доступ из самого класса и его наследников.
2. `private` - доступ только внутри текущего класса.
3. `public` - доступ из любого кода, где виден тип.
4. Поля ссылочного типа обычно инициализируют в конструкторе или при объявлении; `const` инициализируется только при объявлении, а не в конструкторе.
5. `this` - ссылка на текущий экземпляр класса.
6. Поля описываются как переменные уровня класса с модификатором доступа и типом.
7. Объекты класса создаются оператором `new`, например `var ed = new Editor();`.
8. Нестатический метод вызывается через объект: `ed.AddDigit(5);`.

## 4. История (`History`)

1. `List<T>` - обобщённая динамическая коллекция: хранит элементы типа `T`, поддерживает добавление, индексный доступ, удаление и подсчёт.
2. `struct` - значимый тип (копируется по значению), обычно для небольших данных; `class` - ссылочный тип (копируется ссылка).
3. Экземпляры `struct` создаются как `var r = new Record(...);` или без `new` с последующей инициализацией полей.
4. `private` ограничивает доступ члену только рамками текущего класса.
5. `public` делает член доступным для внешнего кода.
6. Для ссылочных полей инициализация в конструкторе гарантирует корректное начальное состояние; `const` задаётся при объявлении, `readonly` можно задавать в конструкторе.
7. `this` внутри экземплярного метода указывает на текущий объект и позволяет различать поля и параметры с одинаковыми именами.

## 5. Управление (`Control_`)

1. Инкапсуляция в `Control_` выражается тем, что управление состоянием, вызовы конвертера и ведение истории объединены внутри одного класса с публичным интерфейсом `DoCmnd`.
2. Поле задаётся внутри класса: например `public History his = new History();`.
3. Метод задаётся сигнатурой: например `public string DoCmnd(int j)`.
4. Простое свойство задаётся как `public int Pin { get; set; }`.
5. Методы класса могут менять внутреннее состояние объекта (`St`, `Pin`, `Pout`) и возвращать результат вычислений.
6. Конструктор инициализирует начальные значения полей/свойств и гарантирует корректное начальное состояние объекта.
7. Видимость членов определяется модификаторами (`private/public/...`) и ограничивает доступ к данным извне.
8. Экземплярные методы вызываются через объект (`ctl.DoCmnd(19)`), статические - через имя класса.

## 6. Интерфейс приложения (WinForms)

1. `Button` - компонент для запуска команды пользователем (обычно по `Click`).
2. `Label` - компонент для вывода текста/подписей, включая отображение текущего ввода и результата.
3. `TextBox` - компонент для текстового ввода/редактирования строки.
4. `TrackBar` - компонент выбора числового значения перемещением ползунка по диапазону.
5. `NumericUpDown` - компонент ввода числа с ограничением диапазона и шаговым изменением.
6. `Load` возникает после создания формы и перед её первым отображением.
7. `Click` возникает при нажатии пользователем на кликабельный компонент (например, кнопку).
8. `Scroll` возникает при изменении положения `TrackBar`.
9. `ValueChanged` возникает при изменении значения компонента (например, `NumericUpDown`).
10. `KeyPress` возникает при вводе печатного символа с клавиатуры.
11. `KeyDown` возникает в момент нажатия клавиши (включая служебные клавиши).
