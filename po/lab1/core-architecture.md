# Архитектура ядра приложения `ConverterLab1`

## 1. Роль ядра

Ядро отвечает за:
- хранение и редактирование введённого числа;
- преобразование числа между системами счисления `p1 -> p2`;
- хранение истории преобразований;
- управление состоянием конвертера (`Редактирование` / `Преобразовано`).

Ключевая точка оркестрации: класс `Control_` (`lab1/src/ConverterLab1/Control_.cs`).

## 2. Основные компоненты

### 2.1 `Control_` (координатор)

Файл: `lab1/src/ConverterLab1/Control_.cs`

Содержит:
- `Editor ed` — объект редактирования числа;
- `History his` — объект истории;
- `Pin`, `Pout` — основания исходной и целевой систем счисления;
- `St` — состояние.

Ключевые методы:
- `DoCmnd(int j)` — центральный обработчик команд;
- `RecalculateWithoutHistory()` — пересчёт без записи в историю;
- `acc()` — вычисление точности дробной части результата.

### 2.2 `Editor` (редактор числа)

Файл: `lab1/src/ConverterLab1/Editor.cs`

Хранит число как строку (`Number`) и реализует редактирование:
- ввод цифры (`AddDigit`);
- ввод `0` (`AddZero`);
- ввод разделителя дробной части (`AddDelim`);
- удаление справа (`Bs`);
- очистка (`Clear`);
- смена знака (`ToggleSign`);
- универсальный диспетчер редактирования по команде (`DoEdit`).

### 2.3 `Conver_P_10` (из `p` в `10`)

Файл: `lab1/src/ConverterLab1/Conver_P_10.cs`

Ключевые операции:
- `char_To_num` — перевод символа цифры в числовое значение;
- `dval` — парсинг строки числа в основании `p` и получение `double` в десятичной системе.

### 2.4 `Conver_10_P` (из `10` в `p`)

Файл: `lab1/src/ConverterLab1/Conver_10_P.cs`

Ключевые операции:
- `int_to_P` — перевод целой части;
- `flt_to_P` — перевод дробной части поразрядно;
- `Do` — полное преобразование (знак + целая часть + дробная часть).

### 2.5 `History` (журнал)

Файл: `lab1/src/ConverterLab1/History.cs`

Сущности:
- `Record` — запись истории (`p1`, `p2`, исходное число, результат);
- `History` — список записей, индексатор и операции добавления/очистки/подсчёта.

## 3. Командная модель ядра

Ядро работает через коды команд `j`.

Базовые коды:
- `0..15` — ввод цифр;
- `16` — разделитель дробной части;
- `17` — backspace (`BS`);
- `18` — очистка (`CL`);
- `19` — выполнить преобразование (`Execute`);
- `20` — смена знака (`+/-`).

Обработка идёт через `Control_.DoCmnd(j)`:
- при `j == 19` выполняется преобразование и запись в историю;
- иначе команда делегируется в `Editor.DoEdit(j)`, состояние переводится в `Редактирование`.

## 4. Поток преобразования при `Execute`

Последовательность:
1. Берётся текущее текстовое число: `ed.Number`.
2. Вызывается `Conver_P_10.dval(ed.Number, Pin)`.
3. Вычисляется точность `c` методом `acc()`.
4. Вызывается `Conver_10_P.Do(decimalValue, Pout, c)`.
5. Результат сохраняется в историю `his.ДобавитьЗапись(Pin, Pout, input, result)`.
6. Состояние становится `Преобразовано`.

## 5. Автопересчёт без логирования

Для смены `p2` используется `Control_.RecalculateWithoutHistory()`:
- выполняет тот же пересчёт, что и `Execute`;
- не добавляет запись в историю.

Это позволяет:
- показывать актуальный результат при смене основания результата;
- не засорять историю промежуточными пересчётами.

## 6. Вычисление точности

Метод: `Control_.acc()`.

Текущая реализация:
- берёт количество знаков после точки у введённого числа (`ed.Acc()`);
- масштабирует его под отношение оснований `p1/p2`;
- ограничивает снизу значением `1`.

Замечание:
- дробная часть в `Conver_10_P.flt_to_P` формируется поразрядно с `Math.Floor`, то есть фактически усечением до рассчитанной длины, а не математическим округлением последнего разряда.

## 7. Валидация и ошибки

Проверки выполняются в преобразователях:
- основание только `2..16`;
- допустимые цифры зависят от основания;
- строка числа должна быть корректна;
- разделитель дробной части допускается только один.

При ошибках выбрасываются исключения (`ArgumentException`, `ArgumentOutOfRangeException`), которые на уровне UI показываются пользователю через `MessageBox`.

## 8. Связь с UI

UI (`MainForm`) не выполняет арифметику напрямую:
- формирует команды `j`;
- изменяет `Pin/Pout`;
- вызывает методы `Control_`;
- показывает `labelInput`/`labelOutput`.

Таким образом, вычислительная логика изолирована в ядре (`src/ConverterLab1`), а `WinForms` выполняет роль представления и маршрутизации пользовательских действий.
